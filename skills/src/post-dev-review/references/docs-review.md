# 使用文档的整体重编排

只在文档阶段读取。以读者能完成任务为标准，区分操作说明、概念边界、维护参考和历史证据。

## 先读全，再确定内容归属

枚举 README、用户指南、配置样例、命令帮助、相关链接与历史记录；区分手写源文档、生成页面和纯开发者资料。
完整阅读当前范围内的内容，核对必要实现；不从标题、目录或搜索片段推断全文已经一致。

为重要主题指定主要说明位置：项目是什么、首次准备、日常使用、协作或集成、诊断与恢复、维护更新、边界和验收证据。
这是内容归属判断，不是必须建立的文件清单。小项目可在一个 README 中表达，大项目再按使用任务拆分。
生成文档应调整其来源，沿用项目生成流程。

## 按真实任务重写叙述

检查读者能否顺着操作完成一次任务：

- 区分首次准备与重复使用，明确哪些步骤只执行一次。
- 在命令前给出所需目录、身份、环境状态和数据前提，避免读者执行后才看到限制。
- 分清观察状态、准备条件、执行工作与停止服务等动作；诊断入口不一定会修复或启动环境。
- 说明使用哪一份配置、源码或构建结果，避免把独立副本、缓存或历史包误当实时来源。
- 给出结果判定和失败后的继续位置；重要限制留在当前指南中，不全部藏进历史记录。

对因反复增补而断裂的段落整段重写。删除废弃入口、过时默认值和无读者用途的实施细节；必要原理保留在参考说明，
不把内部模块命名和维护过程堆进日常流程。必要前提可以在执行点简短重申，详细定义集中维护并互相链接。

## 保留历史与验收边界

把“当前怎么用”与“某日验证过什么”分开。当前摘要按能力、证据和缺口编排；具体阶段的提交、文件摘要、测试计数、
环境和失败记录保留在带日期的明细或项目既有证据系统中，并修复相应索引。

归档不删除未解决问题，也不把历史授权、安装或网络快照写成当前保证。离线测试、实际运行、业务构建与人工质量分别表述；
一次成功不能替代其他层次的验收。文档整理本身不构成新的业务或实机验收。

## 核对重编排后的整体

从主入口重新阅读每条常用路径，检查首次使用、日常使用和失败恢复是否各自连贯，参数或前提是否在多页互相矛盾。
检查重命名后的相对链接、锚点、导航和跨页引用；保留项目需要的公开链接兼容方式。

按文档格式和项目工具检查示例语法，并对照真正的参数解析、帮助或配置规则。
命令示例的语法检查、帮助检查和真实执行要分别记录；不能为了验证文档而直接执行安装、清理、登录或发布命令。
没有现成检查器时使用与实际 Markdown 或文档格式匹配的方法，避免用简化匹配规则声称覆盖全部语法。

最后复核非文档文件和既有用户改动是否保持；如获授权同时修复代码，明确报告对应范围。
