# 代码冗余与兼容性审视

只在代码阶段读取。目标是减少理解和维护负担，同时保留当前契约；一处写法出现多次或看似老旧，不能单独构成删除依据。

## 先还原行为与交付路径

从公开入口追踪输入校验、核心调用、状态写入、失败路径和输出；同时查看配置、测试、构建或安装清单。
确认哪些文件在开发目录执行，哪些会被复制、打包、生成或作为公开库使用。

横向比较看似重复的逻辑：输入是否相同，位于哪个信任边界，何时执行，失败会保护什么状态。
写入前后、授权前后或传输前后的同类检查可能分别检测期间变化，不能仅按表达式相似就合并。

## 对候选项取证

| 候选项 | 需要核对的事实 | 调整原则 |
| --- | --- | --- |
| 重复常量、解析或策略判断 | 是否同一规则；配置来源、语义和变更频率是否一致 | 稳定规则可统一维护；不同信任边界的校验职责仍应保留 |
| 旧格式、路径回退或版本分支 | 支持矩阵、实际消费者、配置迁移、安装环境是否仍需要 | 仅删除已确认退出支持范围的分支；同时核对调用方与错误提示 |
| 静态搜索无引用的函数或导出 | 动态注册、插件、命令分派、外部调用、安装脚本是否使用 | 无仓库内引用不等于无消费者；依证据删除或明确保留用途 |
| 包装、转发、动态加载或多余抽象 | 是否承担环境隔离、所有权、接口稳定或可替换依赖的职责 | 纯转发可简化；不以新层次换取表面上的行数减少 |
| 宽泛异常、重试、默认值和清理 | 原始错误、部分成功、资源归属、成功标记与后续恢复的契约 | 避免掩盖主错误或虚报成功；不擅自把失败处理改为全量回滚 |

代码与测试可能一起沿用过时假设。用公开契约、独立观察或最小复现判断实际影响，不能把现有测试通过当作保留一切的理由。
反过来，测试数增加、文件变少或统一了命名，也不足以证明行为改善。

## 选择结构并完成修改

对每项抽取或拆分说明具体收益：哪些修改点会减少、依赖方向是否更清楚、是否增加初始化或环境耦合。
优先复用现有边界；新增模块需要同步所有实际消费方式，防止出现反向导入、重复初始化或源码目录专属的回退。

涉及生成物或安装布局时修改其权威来源和清单，按项目约定生成产物；必要时从临时交付目录加载入口，
隔离开发目录及额外搜索路径。临时布局验证不能描述为真实新装通过，也不要求为结构整理重建实际环境。

## 让验证能检出问题

针对真实风险选择断言，例如非法输入在副作用前拒绝、部分失败的状态可观察、原始错误不被清理错误覆盖、
成功标记包含必要完成条件、公开入口仍可调用。兼容分支变更还需覆盖支持范围内的保留行为及范围外的明确拒绝。

复现和测试替身要到达目标路径，排除更早失败导致的假阳性。涉及资源或外部系统时，先确认测试已隔离相关副作用；
仅更换 HOME 或模拟一个命令，未必隔离了全部状态与网络操作。

无法获得真实平台或运行证据时保留限制。对决定保留的重复校验和兼容分支，记录其当前用途即可，不堆叠假想风险。
